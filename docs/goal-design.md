# 「目标」模块设计方案（替代现有「计划」）

> 状态：待评审，未写代码。
> 前提：不引入依赖、不联网、数据仍在本地 IndexedDB。
> 现有实现：`ST.plans` = `{id, week, kind:'must'|'stretch', title, done, doneAt, createdAt}`，只有周维度，页内算「必做达标率」。

---

## 0 一句话结论

「非量化目标怎么判定完成」不是技术问题，是**定义问题**。软件能做且只该做一件事：**在你还有意愿的时候，逼你把「什么叫做到」写下来**。
技术上则只做一件事：把四种判定方式统一成 `current / target` 一个比值，进度条、分解、复盘全部复用同一套渲染。

---

## 1 先说清楚「非量化」到底卡在哪

「学完一门外语」这句话里没有可判定的边界：

- 没有终点值 —— 不像「10 万」有一个数
- 没有自然截断 —— "学完"是谁说的算？N1？能点菜？能读小说？
- 没有验收人 —— 自己说学完了，自己也不信

所以它现在只能变成两种坏结果之一：

| 做法 | 结果 |
| --- | --- |
| 给个勾选框 | 三个月后手一抖勾上，目标变成自我欺骗的记录 |
| 永远不勾 | 躺在列表里当负债，每次翻到都内疚一次 |

**结论：目标必须可判定，不可判定的叫方向。** 软件的正确姿势不是替用户判断，而是**在创建时就拒绝模糊表述**，并给出三条合法化路径。

---

## 2 统一模型：四种判定器，只是 `current` 的四个来源

这是整个方案的地基，先立住它，后面全部变简单。

```
                    ┌── metric：数字（手填 或 关联记账）
   目标的 current ──┼── steps ：已完成阶段数
                    ├── accum ：累计值（点一下 +1 次 / +0.5 小时）
                    └── once  ：0 或 1
                                    ↓
                        pct = current / target
                                    ↓
              进度条 / 节奏判断 / 分解 / 复盘 —— 全部共用
```

四种类型对用户是四句话，对代码是一个结构：

| 类型 | 用户看到的一句话 | `current` 从哪来 | 典型目标 |
| --- | --- | --- | --- |
| `metric` 数字 | 「到一个数就算成」 | 探针自动算 / 手填 | 存款 10 万、读书 50 本、体重 70kg |
| `steps` 阶段 | 「分成几步，走完算成」 | 已勾选阶段数 | 学完一门外语、装修完、上线 v1 |
| `accum` 累计 | 「攒够多少算成」 | 累计值 | 学满 150 小时、跑 500 公里、写 10 万字 |
| `once` 了结 | 「做到就算成，写清什么叫做到了」 | 0 / 1 | 考过科目二、辞职、搬完家 |

**为什么不是五种六种**：多一种类型就多一套表单分支、多一处渲染特判。四种覆盖了我能想到的全部现实目标，且都能折回 `current/target`。

### 2.1 数据模型

```js
// store: goals（新表，不碰 plans）
{
  id: "g_xxx",
  title: "存款达到 10 万",
  period: "year" | "month" | "week" | "open",   // open = 不设期限的长期目标
  key: "2026" | "2026-03" | "2026-W12" | "",    // 周期标识，open 型为空

  kind: "metric" | "steps" | "accum" | "once",
  sense: "up" | "down",        // up 越多越好；down 越少越好（限额型）

  target: 100000,              // metric/accum 的终点；steps 不用（= steps.length）
  unit: "元",                  // 元 / 本 / 小时 / 次 / 公里 / 阶段

  // metric 专用
  probe: { t: "balance" }
       | { t: "net",  from: "2026-01-01", to: "2026-12-31" }
       | { t: "cat",  cat: "fun", dir: "out", from: "2026-01-01", to: "2026-12-31" }
       | null,                 // null = 手填
  manual: 0,                   // 手填当前值（probe 为 null 时用）
  base: 62400,                 // 创建时的实际值，只用来画「节奏参考线」，不参与 pct

  // steps 专用
  steps: [ { id, text: "通过 N3 模拟考（≥95 分）", done: false, doneAt: 0, evidence: "" } ],

  // accum 专用
  acc: { v: 0, step: 0.5 },    // 当前累计值、每次默认增量
  accLog: [ { at, n } ],       // 便于撤销与复盘（不上限，但超过 500 条折叠）

  // once 专用
  finish: "收到成绩单，总分 ≥95 且各项 ≥19",   // 完成判据，创建时必填

  done: false, doneAt: 0, review: "",          // 结项 + 一句话复盘
  parentId: "",                // 分解出来的子目标指回父目标
  priority: "must" | "stretch",// 沿用旧的必做 / 弹性
  createdAt, archivedAt: 0
}
```

`probe.from/to` 存 `"2026-01-01"` 字符串而不是时间戳，理由是备份 JSON 打开要能看懂——这条符合你「十年后还可读」的判据，解析成本可忽略。

### 2.2 进度与节奏

```js
function goalNow(g) {
  if (g.kind === "once")  return g.done ? 1 : 0;
  if (g.kind === "steps") return g.steps.filter(s => s.done).length;
  if (g.kind === "accum") return g.acc.v;
  return g.probe ? probeValue(g.probe) : (g.manual || 0);
}
function goalTarget(g) { return g.kind === "steps" ? g.steps.length : g.target; }
function goalPct(g) {
  const t = goalTarget(g), n = goalNow(g);
  if (!t) return 0;
  return Math.round((n / t) * 1000) / 10;      // 保留一位小数，不封顶
}
```

- 达成型（`sense:up`）允许超过 100%，显示 `118%` 并标绿——超额是好事，别裁掉。
- 限额型（`sense:down`）超过 100% 标红，副标题换成「已超 ¥320」。

**节奏判断比进度条本身更重要。** 年度目标 60% 这个数字没有意义，有意义的是「时间过了 80%，你只做了 60%」：

```js
const pace = (Date.now() - periodStart) / (periodEnd - periodStart);  // 0~1
const gap  = goalPct(g) / 100 - pace;
gap < -0.15  → "落后"（橙色）
gap <  0.05  → "跟上"（灰）
else         → "超前"（绿）
```

在进度条轨道上直接画一条细竖线标出「此刻应在的位置」，比任何文字都直观。`base` 只在 metric + probe 型上用：把 `base → target` 当区间画，避免「6 月才开始用，进度虚高」。

## 3 量化目标：三种探针，先分清「存量」和「流量」

这是最容易做错、也最容易让用户觉得「数字不对」的地方。

| 探针 | 算什么 | 用户语言 | 典型目标 |
| --- | --- | --- | --- |
| `balance` 存量 | `nowBalance()` = 期初 + Σ收 − Σ支 | 「余额**达到** 10 万」 | 存款目标 |
| `net` 期间流量 | 区间内 `Σ收入 − Σ支出` | 「**今年**净存 5 万」 | 年度储蓄、年度结余 |
| `cat` 分类流量 | 区间内某分类（含二级）`Σ` | 「今年旅行**不超过** 5000」 | 预算上限、专项花销 |

**「存款 10 万」在这三者里是不同的目标**，必须让用户自己选，选错了数字立刻不对：

- 存款达到 10 万 → `balance`，`pct = 余额 / 100000`
- 今年存下 10 万 → `net`，`pct = 净额 / 100000`（净额为负时 pct 取 0，副标题显示「本月为负」）
- 今年少花 5000（相对去年）→ 这个先不做，需要同比基线，成本不划算

**表单里三种探针用中文说人话，并实时回显**：

```
关联记账：  ● 余额达到        ○ 这段时间净存        ○ 某个分类花掉
            现在 ¥62,400，已达成 62%          ← 当场就能看出选对没有
```

实时回显这一行是防错的关键，比写多少说明文字都管用。

`cat` 探针要能选一级分类（自动含全部二级），复用统计页现成的聚合函数即可。

## 4 非量化目标：三条合法化路径 + 一个体检门槛

### 4.1 创建时强制走「体检」

输入标题后点下一步，先过一道静态规则（纯前端词表，零成本）：

```
命中模糊词：学完 / 学会 / 掌握 / 精通 / 提升 / 加强 / 坚持 / 改善 / 更多 / 更少 / 努力 / 尽量 / 好好
   → 「这句话软件判定不了完成。选一种判定方式，或者改成能被外人验收的写法。」
字数 < 6      → 「太短了，三个月后你自己也看不懂」
选了 metric 但 target 为空 → 直接拦住
```

体检的价值不在拦截，在于**把「想清楚」这一步放在创建时刻**——那时你有意愿、有上下文；等到 12 月 31 日复盘时才想，只剩沮丧。

### 4.2 「学完一门外语」怎么改：三份可抄的作业

**A. 阶段型（推荐，语言学习首选）**

```
标题：日语能读完一本原版小说
判定：阶段（5 步）
  1. 五十音听写全对（能默写，无提示）
  2. 读完 1 本 N4 分级读物，不查词典能懂 80%
  3. 通过 N3 模拟考（≥95 分）
  4. 完成 1 次 15 分钟日常对话（录音自评，能听清关键信息）
  5. 读完 1 本原版小说，累计查词 ≤200 个
```

每一步都写成「一个外人能验收」的样子——这是唯一的写作标准。阶段型天然带来一个好处：**卡片上永远只显示「下一步」**，不会让人面对一整个看不到头的目标。

**B. 累计型（适合「每天学一点」的习惯型选手）**

```
标题：日语学满 150 小时
判定：累计，单位小时，每次 +0.5
```

要在界面上写一句提醒：**投入小时数是过程指标，不能证明学会**。否则一年后「我学了 150 小时」会替代「我学会了」成为自我安慰。

**C. 了结型（有硬终点的事）**

```
标题：考过 JLPT N3
判定：了结
完成判据：收到成绩单，总分 ≥95 且各项 ≥19
```

「完成判据」这条字段是 `once` 型的灵魂，也是它区别于「一个大勾选框」的全部原因。写不出判据的，说明这事还不该进目标列表。

### 4.3 阶段型要不要证据

要，但只收文本：

```
阶段 3 已完成 · 2026-11-20
证据：N3 模拟考 132 分，听力 41 / 阅读 45 / 词汇 46
```

不存图片、不存附件——base64 塞进 IndexedDB 会让备份 JSON 从 200KB 涨到几十 MB，违背「十年后可迁移」。要存截图就写一句「截图在相册 2026-11」。

## 5 周期与分解：默认「视图分解」，按需「真实子目标」

你说「年度目标可以分解到每月每周」，这里有两个实现路径，成本差三倍，我推荐前者。

### 方案 A：视图分解（推荐）

年度目标只有**一条记录**。详情页里给一张节奏表，行是月份，列是「应完成 / 实际 / 差」：

```
读书 50 本 · 按月分解
     应读   实读   差
1月   5      4     -1
2月   4      0     -4   ← 2 月整月没读
...
合计  50     18    按时间应读 21
```

「应读」由 `target × 该月天数占比` 算出，用户可以手动改某个月的配额（读书这种有明显淡旺季的必须能改）。「实读」优先取该月的子目标，没有子目标就取手动记录。

优点：零冗余记录、删父目标不会留孤儿、改总量自动重算。
缺点：不能「逐月勾一次独立完成」。

### 方案 B：真实子目标（可选开关）

从年度目标一键生成 12 条月目标，`parentId` 指回父目标；生成后可逐条独立填进度、独立结项；父目标进度 = 子目标加权平均。

只在一种情况下需要 B：**每个月的配额不一样且要分开跟踪**（比如「1–3 月每月 5 本，7–8 月每月 2 本」）。做成详情页里的一个按钮「拆成月目标」，用到才点，不默认生成。

### 周期切换

顶部一条周期条，不是三个 tab：

```
年    月    周          ‹  2026  ›      今天
```

切「月」时右侧自动变 `‹ 2026年3月 ›`。翻到过去就是只读（不能给去年的目标打勾），翻到未来可以预建。默认落在今天所在周期。

**周目标未完成不顺延**——这是你在 README 里已经定下的纪律，保留。但给一个手动的「移到下周」按钮，明确是人为决定，不是系统替你顺延。

## 6 界面结构

```
┌ 目标 ──────── 备忘 ┐          ← 分段照旧，备忘不动
│  年    月    周     ‹ 2026 › │  ← 周期条（点「今天」跳回当前）
├──────────────────────────────┤
│ 存款达到 10 万               │
│ ¥62,400 / ¥100,000     62%   │
│ ▓▓▓▓▓▓▓▓▓░░░┆░░░░░░░░░       │  ← 凹陷槽 + 填充 + ┆ 节奏刻度
│ 落后 3 个月 · 关联余额        │
├──────────────────────────────┤
│ 读书 50 本                   │
│ 18 / 50 本             36%   │
│ ▓▓▓▓▓░░░░░░░┆░░░░░░░░░       │
│ 本月应读 4 本，已读 2 本      │  ← 分解只在这一行提示
├──────────────────────────────┤
│ 日语能读完一本原版小说        │
│ 2 / 5 阶段             40%   │
│ ▓▓▓▓▓▓░░░░░░┆░░░░░░░░░       │
│ 下一步：通过 N3 模拟考        │  ← 只显示下一个未完成阶段
├──────────────────────────────┤
│ ☐ 考过科目二 · 判据已写       │  ← once 压成一行，不占大卡片
├──────────────────────────────┤
│ ＋ 新建目标                   │
└──────────────────────────────┘
```

视觉延续现有「表壳」语言：进度槽用 `--well-*` 那套内阴影，填充用 `--brand`，节奏刻度是一根 1px 的 `--ink-3` 竖线。不引入新色板。

**新建表单**（全屏 sheet，沿用 `sheet-edit` 的壳）：

```
1  一句话目标          [_______________]
2  周期               年 · 月 · 周 · 长期
3  怎么判定算完成      数字 · 阶段 · 累计 · 了结
4  （依类型展开）
      数字 → 关联记账（余额/净存/某分类） 或 手填；目标值 + 单位
      阶段 → 逐步填写（至少 2 步，每步一句可验收的话）
      累计 → 目标量 + 单位 + 每次增量
      了结 → 完成判据（必填）
5  必做 / 弹性
```

第 3 步是核心分叉，**默认选中「了结」**——最快路径是「写一句话 + 选周期 + 保存」，共 3 次操作。其余三项折叠展开，只在需要时增加复杂度。旧的「加一条…」输入栏保留为快捷入口，走 `once` 默认值。

## 7 迁移：懒迁移，不动数据库版本号

现有 `plans` 有 `week`、没有 `period/kind`。**不要写升级脚本、不要动 `DB_VER`**（从 2 升 3 一旦失败，表现是白屏或数据不可见，代价远大于收益）。

改为**懒迁移**：读到一条没有 `kind` 的记录，按旧语义解释：

```js
{ ...p, period: "week", key: p.week, kind: "once", priority: p.kind,
  finish: "做到就算成（旧版计划自动转换）", done: p.done, doneAt: p.doneAt }
```

下次编辑保存时自然补齐字段。旧数据只读不坏，新数据干净。`plans` 表保留不删，作为回滚保险。

## 9 风险与不做的事

**风险 1：表单把「加一条」从 3 秒变成 15 秒。**
缓解：默认走了结型、其余折叠、旧输入栏保留。宁可让 80% 的日常目标用最笨的方式记，也不要为了 20% 的复杂目标把入口做重。

**风险 2：探针口径选错，数字看起来像 bug。**
缓解：中文说人话 + 实时回显当前值 + 详情页写明「这个数是 期初 + Σ收 − Σ支」。

**风险 3：改名后旧用法失配。**
「计划」原来的真实用法很可能是**待办清单**（「打电话给物业」也在里面）。改名「目标」后这类碎条目放哪，是个会踩的坑。处理：`once` 型周目标在列表里压缩成一行、不画进度条，视觉上就退化成清单；同时在迁移提示里写一句「琐碎待办更适合放「备忘」」。不另开待办模块。

**明确不做：**

- 不做打卡日历（与轨迹页职责重叠）
- 不做目标间依赖 / 甘特图
- 不做提醒推送（PWA 无可靠后台，承诺了反而失信）
- 不做 AI 生成目标（要在创建时辅助就用固定词表，可预期、零成本）
- 不做目标分类/标签体系（按周期分组已经够，多一层就是负担）
- 不做目标进度出现在流水里（流水只放流水，这条你已经定过）

## 11 一个额外建议：结项复盘

## 13 第一次反馈后的调整（2026-11-24）

三条反馈，改的是结构而不是模型：

### 13.1 「备忘」改名「计划」，必做/弹性搬过去

目标页原来分「目标 / 备忘」，底部还有一条「必做/弹性 + 输入框」。实际用起来是两套东西混在一页：**目标是「一年做成什么」，必做/弹性是「这周要办什么」**。

现在：

| 段 | 内容 | 数据 |
| --- | --- | --- |
| 目标 | 年 / 月 / 周 / 长期，带进度或判据 | `goals` |
| 计划 | 要办的、要买的，分必做 / 弹性 | `memos`（原「备忘」） |

底部快捷添加条跟着搬到计划页，目标页只留一个固定的「＋ 新建目标」。连带三个后果：

- 目标不再有「强度」，`priority` 字段留着兼容旧数据，新目标恒为 `must`。
- 目标页的达标率滚轮删掉——没有必做/弹性，就没有达标率的分母。
- 旧 `plans`（本周待办）改为迁进计划，不迁进目标。迁移标记换成 `plansMovedToMemo`，**之前跑过 `goalsFromPlans` 的库会重新迁一次**，这是有意的：那批数据本来就该在计划里。

### 13.2 数据来源默认改成「自己填」

原方案把「关联记账余额」当默认，理由是「存款 10 万」最有说服力。但目标里绝大多数是读书本数、跑步公里、学英语这类，默认余额会让它们全显示 0，看着像 bug。

现在的表单：

```
目标      [读完 24 本书]
周期      年 / 月 / 周 / 长期
怎么算完成 数字 / 了结
目标值    [24] [本]
进度从哪来 自己填 / 记账余额     ← 默认「自己填」
           完成多少自己填，读书本数、跑步公里都归这里
现在到哪了 [9]                  ← 选「记账余额」时这一行隐藏
```

选了「记账余额」才把说明换成「直接读当前余额，只适合『攒到多少钱』这类目标」，单位锁定「元」，并实时回显「现在 ¥62,400，已达成 62.4%」。

### 13.3 目标页去掉「强度」

理由同上：强度是待办的属性。表单一共 6 个字段（目标 / 周期 / 判定方式 / 目标值 / 进度来源 / 当前值），比第一版少一个，「新建」这条路更短。

### 修订后的待办

- v0.13 不变：`steps` / `accum` 两种判定器、`net` / `cat` 两种探针、按月分解表。
- 计划段暂不做到期顺延、周归档——它现在是长期清单，没有「周」这个概念。

## 14 第二次反馈：判定收敛到「数字 + @来源」（2026-11-24）

### 14.1 取消了结型，剩下一种判定

删掉 `once` 之后，目标的定义收敛成一句话：**写一个数，让进度算得出来。**

连带删掉四个字段：完成判据（`finish`）、强度（`priority`）、单位（`unit` 输入框）、进度来源下拉。表单从 7 行缩到 4 行：

```
目标       [读完 24 本书 @轨迹]
            @记账余额  @轨迹  @随笔
            进度自动取今年轨迹里的条目数，现在 10 条
周期       年 / 月 / 周 / 长期
目标值     [24]
现在到哪了  [0]        ← 有 @ 时隐藏
```

代价要说清楚：**「学完一门外语」这类目标没有位置了。** 旧数据会被转成 `0/1` 的卡片（`done` 转 `manual`），看起来是「0%」或「已达成」。这类目标要么改写成数字（学满 150 小时、读完 20 本分级读物），要么删掉。这是取消 `once` 的必然结果，不是 bug。

### 14.2 `@` 标记：来源写在句子里

不做下拉，而是让用户在原句后面加标记：

| 标记 | 探针 | `current` 取什么 | 量纲 |
| --- | --- | --- | --- |
| `@记账余额` | `{t:"balance"}` | `nowBalance()` | 存量 |
| `@轨迹` | `{t:"track"}` | 本周期内 `inTrack` 的记账数 + 标「大事」的随笔数 | 流量 |
| `@随笔` | `{t:"note"}` | 本周期内 `notes` 条数 | 流量 |

细节：

- 兼容全角 `＠`，别名 `余额` / `记账` / `笔记`。
- 保存时用 `parseSrc()` 把标记从标题里抠掉，只留干净标题；详情页 / 卡片上用一个 9.5px 的小描边标签标出「余额 / 轨迹 / 随笔」，让用户知道这条是自动算的。
- 表单里三个 chip 点一下就把标记追加到输入框末尾（已有时替换），输入时实时解析、实时回显。
- 周期决定统计范围：年视图数今年，月视图数本月，周视图数本周，长期数全部。**余额是例外**——它没有周期维度，永远取当前值。

### 14.3 为什么轨迹探针这么数

轨迹页（`renderTrack`）只有两种条目：标了轨迹的记账（`inTrack`）和标为「大事」的随笔（`big`）。探针口径必须和用户眼睛看到的一致，否则「进度 10 条」和轨迹页里数出来的对不上，立刻变成信任问题。

由此推出一个使用约定：**「读完一本书」这件事要落进轨迹**——记一笔 0 元标了轨迹的账（`读书 · 读完《XX》`），或者写一条大事随笔。两条路都计入，也都能在轨迹页看到。如果两样都记，会算两次。

### 14.4 还没解决的一个概念问题

`@轨迹` 与 `@随笔` 有重叠：大事随笔既算轨迹也算随笔。目前没做去重，理由是两者语义不同（轨迹=有里程碑意味的事，随笔=所有记录），且重叠只发生在用户同时写了两处的情况。如果实际用起来数字偏大，再改成「轨迹只数 `inTrack` 记账」。

### 14.5 修订后的待办

- v0.13：`net`（今年净存多少，流量）与 `cat`（某类支出不超预算，限额型）两个探针；年度目标按月分解表。
- `steps` / `accum` 两种判定器**不再做**——判定已收敛到数字，加起来就是一道减法：能折算成数的才配叫目标。

## 15 第三次反馈：来源收回、轨迹补录、随笔卡片（2026-11-24）

### 15.1 轨迹与随笔不再当进度来源

三个探针砍到只剩一个：`@记账余额`。

理由不是「实现麻烦」，而是**口径必然歪**：

- **重复计数**：一条「读完《活着》」既可能记成一笔标轨迹的账，也可能写成大事随笔。两条路都计入，同一本书算两次；只记一条路，又跟另一个地方的列表对不上。
- **量纲不对**：轨迹里还有「收入 ¥62,400 · 1 笔」这种汇总行，随笔里还有「今天心情不好」。把它们的**条数**当「读书 24 本」的分子，这个数字从第一天起就是假的。
- **纠错成本高**：数多了以后，用户第一反应是「这软件算错了」，而不是「我记错地方了」。目标一旦不可信，整个模块就废了。

迁移：旧目标里 `probe.t` 是 `track` / `note` 的，启动时把**当时的数冻结成手填**（`migrateProbe()`），进度不掉回 0，之后由用户自己维护。旧习惯还写 `@轨迹` 的，保存时直接拦下并说明。

### 15.2 轨迹补录

轨迹页顶条：左边「N 天 · M 条」，右边「＋ 补录」。

补录表单两行：**哪天**（复用记账页那套自绘日期面板，`openDatePop(curKey, onPick)` 加两个可选参数）、**做了什么**（一句话）。补出来的条目落成 `big:true` 的随笔，`at` 是选的那天 + 补录这一刻的时分。

不补记账的理由：补账要选分类、填金额，记账页本来就能选到过去的任意一天；轨迹缺的是「那天做了什么有意义的事」，不是缺一笔钱。

### 15.3 随笔卡片

| 项 | 原来 | 现在 |
| --- | --- | --- |
| 形态 | 「时间 + 一行文字」的列表行，天与天之间一条分割线 | 一条一张卡片，圆角 15px、`--shadow-2`、卡片下方露出下一层的边 |
| 分组 | 日期组头 | 保留，一天就是一叠 |
| 时间 | 左侧固定 36px 列 | 卡片内顶部小字，跟「大事」标同行 |
| 大事 | 右侧小标签 | 左侧压一道 accent 色条 + 标签，一眼能挑出来 |

「卡片下面露出一条边」用 `.nc::after` 实现：`z-index:-1` 的伪元素伸出卡片底部 4px，露出 12px 高的第二层边缘。深色下这条边几乎看不见（`--surface` 与背景太近），但深色下卡片靠 border 已经分得开，不影响。

### 15.4 顺手修的

- 弹层字段多时（320×568）底部按钮被裁：`.modal-card` 改成 flex 纵向，只滚 `#m-body`，按钮固定；`max-height` 用 `--vh`。
- 目标标题 placeholder 从「读完 24 本书 @轨迹」改成「存款达到 10 万 @记账余额」——占位文字必须示范现在唯一成立的那种写法。

## 16 第四次反馈：目标只到年月、计划以周为周期、轨迹分两段（2026-11-24）

### 16.1 目标只保留「年 / 月 / 长期」，周目标取消

周目标的问题不是「不好算」，而是**周期太短，来不及做、也来不及落后**：一周只够装一件具体的事，那是计划，不是目标。「今年存 10 万」「这个月读 2 本书」才是目标该有的颗粒度。

- 周期条与表单只剩 `年 / 月 / 长期` 三个。
- 存量 `period === "week"` 的目标在启动时转成 `open`（长期）：`target` 与原 `manual` 都不动。不转成月目标是因为「每周 14L」按周算的 target 直接当月用会虚高一倍。
- 落后换算也跟着只剩两档：年目标按「个月」，月目标按「周」。

### 16.2 计划以周为周期 + 每周重复 + 关联目标

计划页顶部一条周导航（`‹ 本周 ›`），列表只装这一周。三条新字段：

| 字段 | 含义 |
| --- | --- |
| `week` | 归属周（`weekKey()`，周一起算，格式 `YYYY-MM-DD`） |
| `repeat: "weekly"` | 每周重复：创建周之后的每一周都自动出现在列表里 |
| `goalId` + `amount` | 挂到哪条目标上，勾一次给它加多少 |

完成状态按条目类型分开存：普通条目一个 `done` / `doneAt`；重复条目用 `doneWeeks: {weekKey: true}`，各周各记，互不干扰。

**口径**：`memoSum(g)` 只累加落在目标 `[from, to)` 内的已完成量。重复条目按**那一周的周一**归属——11/30 那天属于 11 月，但它所在的周算 12 月，这条周计划就算进 12 月。跨月周不劈开算，劈开等于把「一周喝 14L」拆成 2 + 12，没人会那样记。

**为什么不把「完成后同步进度」做成勾一下就自动改目标数值**：勾选是离散动作，目标是连续量。做成「勾一次 +14」写在计划上，改口径时只改一条计划，不用回头修目标。

### 16.3 轨迹拆成「大事记 / 空间」

同一个数据集，两种切法：

- **大事记**：按天倒序的时间轴（原来的样子）——回答「什么时候发生了什么」。
- **空间**：按地点聚合（`notes.place`）——回答「在那个地方发生过什么」。

`place` 是大事的自由文本（「杭州 · 西湖」），不建地点表：个人使用场景下地点是随手写的，做成实体列表反而要维护、要去重、要处理「西湖 / 杭州西湖 / 西湖景区」三个名字。分组时按字符串原样聚，一年下来几十个地点，肉眼看得出重复，改名成本比维护字典低。

入口两处：补录时可以直接填；大事记里点任意一条，弹出「这一条」改文字、补地点。没填地点的大事不进空间页，空间页底部会写「还有 N 条没写地点」。

轨迹 tab 从第 3 位挪到第 4 位（记账 / 目标 / 随笔 / 轨迹）：轨迹是回看入口，不是日常录入入口，排在最后才符合使用频率。

### 16.4 日期面板加年月快选

补录要选 1990 年的某天，原来只能一个月一个月往前点，四百多下。

现在点标题（`2026年11月 ▾`）展开年份网格：今年往下到 1970，四列可滚；点年 → 落成月份网格（`‹ 1990年` 可返层）；点月 → 收回，日网格刷新。三层都是同一块 `#dp-quick` 容器，`dpQuick` 三个状态（`""` / `"y"` / `"m"`）。

小屏（`max-height: 620px`）把年份区压到 152px，日历不被挤没。

### 16.5 顺手修的两个存量 bug

1. **弹层监听器残留**：`openModal()` 只清 `#m-body` 的 `innerHTML`，而 `onOpen` 里的 `click` 是绑在 `#m-body` 元素本身。第二个弹层里出现同名控件（`.g-chip`）时，第一个弹层的处理器还在响应，去读已被销毁的 `#ge-target`，`null.value` 直接抛错。改为每次 `cloneNode(false)` 换一个新节点。
2. **记账页日期按钮点了没反应**：`addEventListener("click", openDatePop)` 把 event 顶进了 `curKey` 参数，`dpSel.split` 立刻抛错。改成 `() => openDatePop()`。

## 17 第五次反馈：三种 @ 来源、计划弹窗、空间上地图（2026-11-24）

### 17.1 `@` 来源回到三种

上一轮把轨迹与随笔的探针全砍了，理由是「口径会歪」。这一轮要求回来，那就得把口径重新定清楚：

| 标记 | 取什么 | 性质 |
| --- | --- | --- |
| `@记账余额` | `nowBalance()` | 存量，只有「现在」这一个值 |
| `@大事记` | 目标周期内 `big:true` 的随笔条数 | 流量，按 `[from, to)` 数 |
| `@随笔` | 目标周期内全部随笔条数 | 流量，按 `[from, to)` 数 |

`probeCount(t, from, to)` 带范围，`goalNow(g)` 把目标的 `from/to` 传进去；长期目标没有范围，就数全部。

上一轮砍它的两个理由，现在各有一个交代：

- **重复计数** → 现在只剩「大事」一个口径，不再把「标了轨迹的账」和「标大事的随笔」加在一起算。想数读书就只写大事，想数随手记就用随笔，两者不混。
- **量纲不对** → 目标写「今年读 24 本书」时，大事记里就不该出现「今天心情不好」；这是写的人的责任，程序能做的只是把范围锁在周期内。

迁移：老的 `probe.t === "track"` 不冻结了，直接改成 `"mile"` —— 那个口径本来就是轨迹页的第一条（大事）。

### 17.2 计划：新建走弹窗，且不许重复计数

底部那条「必做 / 弹性 + 输入框 + ＋」撤掉，换成一个「＋ 新建计划」按钮，点开弹窗：

内容 / 类型（必做·弹性）/ 关联目标 / 算多少 / 每周重复。点条目上的 `⋯` 或长按，打开同一个弹窗（多一个删除）——字段完全一样，不值得两套表单。

「关联目标」点开是一个内联展开的列表，不是二级弹层：二级弹层要替换 `#m-body`，已经填好的文字和数字全丢。列表按 年度 → 月度 → 长期 排，右侧标「年度 · 37.5%」。

**关键一条**：有 `probe` 的目标在列表里写「自动 · 不用挂」，点它只会弹一句提示，不会选中。因为「今年读 24 本书」已经在大事记里数着了，再挂一条「一周读 2 本」的计划，读一本书会被算两遍。宁可当场说清楚，也不给一个挂着不生效的入口。

无 `probe` 的目标（自己填进度的那种）才是计划的正确搭档：勾一次加 `amount`，`memoSum()` 累加，卡片上写「计划 +2」。

### 17.3 「补录」改名「新建大事记」

功能没变（选哪天 / 写一句 / 可填地点），只是把入口的名字从「补录」改成「新建」、弹层标题改成「新建大事记」。理由是「补录」暗示「这是事后补的」，而绝大多数时候就是当场记一条。

### 17.4 空间：真地图，还是手绘的

地点是自由文本，没有经纬度。要落到地图上，需要三样东西：轮廓、坐标、匹配规则。

**轮廓**：33 个省界多边形，从公开行政区划数据里解码（echarts 的编码格式：`encodeOffsets` + zigzag 差分字符串），Douglas-Peucker 抽稀到 0.08 度，坐标量化到 0.1 度并转成相对指令（`l3 -7`），最终 15KB。手绘感来自：省界只一层淡填充 + 细描边，去过的地方填淡绿，没有阴影、没有标注、没有图例。

**坐标**：210 条「城市 经度 纬度 省」，约 5KB，覆盖直辖市、省会、地级市与常见旅行地（阳朔、敦煌、香格里拉、长白山这类）。补了 31 条省名 → 省会坐标，所以写「浙江省」也能定位。

**匹配**：`placeAt(text)` 用「文本包含城市名、长名优先」。中文地名互含很常见（吉林 / 林、南京 / 京、海南 / 南海），长名优先能挡住大部分误判；认不出的不猜，列表里标「未定位」，顶部提示「写上市名就能定位」。

**投影**：`x = (lon - 73.5) × 10`，`y = (53.6 - lat) × 12`，viewBox `-12 -10 640 448`。纬向乘 1.2 是补等距圆柱在高纬度的拉伸，视觉比例接近常见的中国地图。

**南海诸岛**：主图只到 lat 18，直接扩 viewBox 会把大陆压扁，所以按标准做法做成右下角小插图（岛点 + 断续线示意），图下角标「示意 · 只到城市」。

**交互**：点地图上的城市 → 下方列表滚到该城市第一组并闪一下（列表组带 `data-city`）。地图上的点面积随条数开方增长（`6 + √n × 3`，上限 15），标签「放得下才放」，先到的大城市占位，挤不下就不写。

### 17.5 顺手修的

- **切页重算**：大事 / 随笔成了目标的自动来源之后，在轨迹页新建一条大事、回到目标页，卡片还停在旧数字上（`renderGoals()` 只在保存计划时调）。改成 `setView("plan")` 时重算一次，兜住所有数据入口。
- 删掉 `.add-bar` 的样式和 `ST.memoKind`：计划不再有底部输入条，这套东西没人用了。

## 18 v0.15：把「自动关联」全拆掉

上一版把三样东西绑在了一起：随笔标了大事就同时出现在两个页面；目标可以数大事记和随笔的条数；大事记页顺手把每天的支出也汇总进去。用起来的问题是一样的——**你在一个地方写的东西，在另一个地方自己长出来了**。这一版把三条线全部切断。

### 18.1 随笔与大事记：同表不同命

`notes` 还是同一张表，加一个 `kind`：`"note"` 或 `"mile"`，写入时就定死，之后靠它过滤。

- 随笔页只查 `kind !== "mile"`，大事记页只查 `kind === "mile"`。
- 新建大事记（轨迹页「＋ 新建」）直接写 `kind:"mile"`，**不落进随笔**。
- 随笔要进大事记，只有一条路：点开这张随笔 → 「标为大事记」。这条记录随即从随笔列表消失、出现在大事记里。
- 编辑器上的「写成大事记」等于「这条不开头就记成大事记」，语义一致。

为什么是「挪过去」而不是「两边都有」：两边都有就是自动同步换了个触发方式，删除、改字、前后顺序全要维护两套。一条记录只属于一边，逻辑上只有一个真值。

迁移：`big:true` → `kind:"mile"`，然后删掉 `big`。备份恢复后也跑一遍，老备份照常能用。

### 18.2 目标只剩年度

月目标和长期目标一起取消。理由不是「用得少」，是**它们各自破坏了同一个东西**：

- 月目标让「节奏刻度」失真——一个月里「落后约 1 个月」等于全月归零，没有中间态。
- 长期目标没有 `to`，`paceOf()` 返回 null，进度条上那条竖线永远不出现，就退化成一根普通进度条。

两个都并进当年（`period:"year"`，`key` 取原 `from` 所在年，`from/to` 重算成整年）。目标值、已填进度都不动。

来源同理收口：只认 `@记账余额` 和挂在目标上的计划。`@大事记` / `@随笔` 两种探针取消——它们数的是流量，年度目标要的是存量结果，而且和 18.1 的「两边各存各的」直接冲突。旧数据里这两种探针**断开并冻结**成当时的条数（`manual = 那一刻的数`），不让进度突然归零。

### 18.3 大事记页不再混记账

原来每个有账的日子都会在轨迹里留一行「支出 ¥1,866.50 · 1 笔」，理由是「回看轨迹顺便看花费」。实际效果是：记了三个月账，大事记页翻十屏都是支出，自己写的那几条被埋掉。

现在只有两种东西进大事记：`kind:"mile"` 的记录，和你手动点了「轨迹」开关的单笔账。每日汇总那一行连同 `d.out/d.inc/d.n` 一起删了，`touch()` 里不再为每笔账建日期节点。

### 18.4 界面：只留主文案

这一版删掉的东西，按类分：

| 类型 | 例子 | 处理 |
| --- | --- | --- |
| 分组小标题 | 「必做 / 弹性 / 已完成」「长期」 | 删。弹性靠圆形选框区分，已完成靠划线，顺序恒定 |
| 统计小结 | 「本年 2 个目标 · 平均 11% · 2 个落后」「20 天 · 2 条」「还剩 2 条」 | 删。数字在卡片上，不需要再来一遍 |
| 标题副文案 | 「统计分析 · 近 12 个月」「支出明细 · 按金额排序」「月度报表 · 点金额看账单」 | 删 `<em>`，保留主标题 |
| 表单提示 | 「后面接 @ 就能自动数」「勾上这条计划，就给选中的目标加进度」 | 删。字段名和 chip 已经说明了 |
| 空态副句 | 「点上面的按钮，记第一笔」 | 删，只留「还没有账」 |
| 长说明 | 我的页「说明」整段、底部留白开关的解释 | 删 |

判断标准只有一条：**这句话如果删掉，用户会不会做错事**。会（「标为大事记」这种动作入口、删除确认）就留；不会（解释这个功能怎么用）就删。

### 18.5 顺手修的

- `periodRange` / `periodShift` 只剩年度分支，`paceOf` 的 `null` 情况只可能来自脏数据。
- `renderGoals` 不再需要「长期」那一段，`setGoalPeriod` 整个删掉，`goal-nav` 加 `margin-left:auto` 顶到右边。
- 计划列表第一段去掉 `margin-top`，没有小标题之后原来那 14px 会变成一段莫名其妙的空隙。

## 19 v0.16：地图做到区县，并且能放大

上一版的地图只有省级轮廓加 210 个城市点，放大就是放大一层糊的线条。这一次把底图换成三级行政边界，并给它一套缩放。

### 19.1 数据从哪来、怎么压

公开行政区划数据（DataV 的 `areas_v3`）提供到区县一级的 GeoJSON。抓下来是 34 个省、363 个市、2871 个县级单位，原始坐标约 112 万个点、23MB。

压到能塞进单文件，做了四件事：

| 步骤 | 做法 | 效果 |
| --- | --- | --- |
| 抽稀 | Douglas-Peucker。省 0.03 度、市 0.05 度、县 0.032 度 | 112 万点 → 6 万点 |
| 闭合环处理 | 首尾重合会把整环压成两个点（首尾连线长度为 0，所有中间点都"在线上"）。先找离起点最远的点切成两段，各自 DP 再拼回 | 否则东城区这种小区直接消失 |
| 量化 | `round((lon-73.5)*20)`，一格 0.05 度（约 5km） | 整数坐标，相对指令 `l3 -2` 每点约 4 字节 |
| 分省打包 | 一层一个字符串数组，首段是省 adcode，省下 2871 次重复的省码 | 350KB |

保底规则：每个县至少要有一个环留下来。主环被抽稀到两个点以下时，用 1/6 的容差重抽一次。

代价是 `index.html` 从 231KB 涨到 604KB。gzip 后约 170KB，装成 PWA 后只在首次安装时下载一次。这个取舍是明确的：**离线地图不可能又细又小**，而"点开就能看自己去过哪些区县"是这一页的全部意义。

### 19.2 缩放不是一个比例尺，是三个档

连续缩放的话，县名会在任何中间倍数上糊成一团。所以按档画：

| 档位 | 触发 | 画什么 |
| --- | --- | --- |
| 0 | z < 1.5 | 省界（34 条常驻）、地点与标签 |
| 1 | 1.5 ≤ z < 2.6 | 加市界（只画视口内的省）、市名 |
| 2 | z ≥ 2.6 | 加县界、县名 |

跨档才重建 DOM；拖动和连续缩放只改 `viewBox`，所以拖动时是一帧一帧跟手的，不会每次都重排三千个 path。

市名和县名的排法不一样：

- **市名**按 bbox 面积排序，但**有地点的市排到最前**——否则面积排序会把榜单全让给西部那些面积巨大的自治州，杭州成都一个都看不见。名字先去掉自治州前的民族名（「海西蒙古族藏族自治州」→「海西」），落在自己的点上时上移 26px。
- **县名**居中排在 bbox 中心，19px 行距 / 68px 列距避让。有地点的县不写名——那个点上已经有标签了，写两遍只是重叠。

### 19.3 手势

一次 pointer 事件管三种输入：

- 单指：`MV.z > 1.02` 时才拖动。全国视图下拖动没有意义，让页面照常上下滚。
- 双指：记下初始距离与中点，`pointermove` 按比例改 z，锚点用中点的世界坐标。
- 滚轮 / 双击：桌面与平板顺手。双击两倍，超过 4.5 倍时回到全国（再点就是重置）。

`touch-action` 跟着状态切：z ≤ 1 是 `pan-y`，放大后是 `none`。这是唯一能让"地图内拖动"和"页面滚动"共存的办法。

一个坑：`pointerup` 之后的 `click` 会在拖动结束时误触发点选。用时间戳挡——拖动或捏合时记 `mapMovedAt = Date.now()`，`click` 里 320ms 内的直接忽略。

### 19.4 地点匹配扩到区县

`placeAt()` 现在三步：

1. 手调的 210 条景区名（西湖、灵隐寺、漠河这些，坐标是手工核过的）先比一遍。
2. 文本里出现省名（「浙江 · …」）就限定在这个省，避免「城关区」这种同名县认错。
3. 在 3234 个市区县名里按长度倒序找第一个命中的——长的优先，「西湖区」不会被「西湖」抢先。

坐标取该区县 bbox 的中心。区县的形状不规则时中心可能落在边界外，但对一个打点来说够了。

### 19.5 取舍

- **不做乡镇**。区县已经是 2871 个，乡镇是 4 万个，光数据就 3MB，而且没人按乡镇记地点。
- **不做地图瓦片**。瓦片要联网，离线就白屏；这张图的作用是"看自己去过哪"，不是导航。
- **不做省界以外的国界修正**。边界只作示意，图上不标"示意"两个字——用户自己写的「杭州 · 西湖区」才是这张图的数据来源。
